## 1. 研究背景与动机

### 1.1 问题从何而来

| 阶段 | 任务 | 关键结论 | 状态 |
|------|------|----------|------|
| 前期 | Mercari 整句三分类（弱标注 vs Gold） | Weak Macro F1 0.566，Gold 0.713；**负面识别是共同短板** | 已完成 |
| 中期 | 日语酒店 ABSA（7 方面 × 正负） | `absa_asl_v1` Micro F1 **0.822**，负面聚合 F1 **0.705** | 已完成 |
| 诊断 | 隐式情感子集分析（Task 1 / E1 / E2） | 86% 标签为隐式；隐式负面 F1 比显式低 **4.3 pp** | ✅ 已完成 |
| 代码重构 | 训练工具链整理（training_utils.py + 8 项架构问题修复） | WeightedTrainer 统一、API 兼容、梯度裁剪、临时目录清理等 | ✅ 已完成 |
| **当前主线** | **2024 面板弱监督预训练能否改善 ABSA？** | 面板 58 万条已入库；重叠检查完成（0 条重叠）；全量 CSV 解析待跑 | **本计划重点** |

当前 ABSA 模型在 5.3 万句 Gold 标注上训练，已接近可用（Micro F1 ≈ 0.82），但**负面方面**仍是短板（聚合 F1 0.70）。诊断实验进一步表明：负面标签中 **92% 为隐式表达**（无情感词典命中），隐式子集 F1 显著低于显式。

瓶颈不仅是模型结构，更是**训练数据规模与标签覆盖不足**。与此同时，项目新入库的 `01_Travel_Review.2024.tsv` 提供 **583,778 条**真实酒店评论，每条附带总体评分与 **6 项分项评分**——这是用户本人打的方面级情感信号，质量远高于关键词弱标注，且规模是 Gold 标注的 **10 倍以上**。

### 1.2 核心论点（路线 A）

本研究选择**分项评分弱监督预训练**作为核心方法路线：

1. **诊断证据**（已完成）：在 Gold 标注上量化隐式/显式差距，证明负面 ABSA 确有改进空间；
2. **规模化训练**（主线）：用 2024 面板的 6 项分项评分作弱标签，预训练 XLM-R 编码器，再在 Gold 标注上微调 14 标签 ABSA 头；
3. **严格评测**：所有最终数字仍在 Gold `absa_test.csv` 上报，面板数据**永不**进入 test。

本研究的贡献不是「又一个 ABSA 模型」，而是验证：**真实用户方面评分这一免费弱标签，能否系统性提升句子级 ABSA——尤其在隐式负面子集上**。

### 1.3 与旧版计划的关系

- 旧版以 Gold 5 万句 + 对比学习为主线，**已由本版（路线 A）取代**；
- 对比学习（原 E3/E4）降为**可选附录**，不在必做范围；
- 2024 评论面板从「扩展方向」升格为**主训练语料**；
- 实验编号：E1/E2（诊断）保留；**E7/E8** 为路线 A 主线新增编号。

## 3. 数据与评测体系

### 3.1 双层架构

```
层级 A：2024 评论面板（主训练语料）
  ├─ 原始：gold/data/raw/01_Travel_Review.2024.tsv（583,778 条）
  ├─ 解析后：data/panel_parsed/2024.csv
  └─ 重叠剔除后：data/panel_train_pool.csv（弱监督训练池）

层级 B：Gold ABSA（评测锚点 + 微调集）
  ├─ 原始：gold/data/travel_aspect_sentiment.tsv（76,624 句 / 92,273 标签对）
  ├─ 切分：data/absa_{train,valid,test}.csv（53,192 句，seed=42）
  └─ test 集：永不参与面板训练或重叠剔除前的任何操作
```

| 资产 | 规模 | 角色 |
|------|------|------|
| **2024 面板** | 583,778 条评论，22,142 酒店 | **弱监督预训练主语料** |
| **Gold ABSA** | 53,192 句（annotated-only） | 微调 train/valid + **唯一 test 评测** |
| HotelMaster | 27,603 家 | 酒店聚合分析（应用 demo，可选） |
| 边界样本 | 195 条 | Task 2 人工验证种子 |
| 筑波语料 | 5,308 句 | 附录：域差异讨论 |

**明确不使用**：Mercari 弱标注、旧三分类 checkpoint。

### 3.2 面板字段与弱标签定义

`01_Travel_Review.2024.tsv` 为 18 列无表头 TSV（详见 `data_review_travel_review_2024.md`）：

| 列 | 内容 | 弱监督用途 |
|----|------|-----------|
| 10 | 总体评分（1–5） | 辅助分析 / 可选全局信号 |
| 11–16 | 六项分项评分（1–5，**0=未评价**） | **E7 多任务弱标签** |
| 17 | 评论正文 | 模型输入 |

**弱标签操作化**（E7 预训练任务）：
- 对每个分项评分列，将 `0`（未评价）视为缺失，不参与该列损失；
- 有效评分 ≤ 2 → 负面（label=1），≥ 3 → 非负面（label=0）；
- 6 列各自为一个二分类头（多任务学习）。

> 列 → 方面映射（サービス/立地/部屋/設備・アメニティ/風呂/食事）须在 Phase 0 核验后写入 `data/panel_rating_column_map.json`。

### 3.3 数据使用红线

| 规则 | 原因 |
|------|------|
| Gold test **永不**参与面板预训练、重叠剔除前的任何训练 | 评测有效性 |
| 面板入库后**必须先做重叠检查**，命中评论从训练池剔除 | 防数据泄漏 |
| 原始 TSV **不入 Git**（`gold/data/raw/` 加入 `.gitignore`） | 许可与体积（NII-IDR 协议） |
| 弱监督预训练只用 `panel_train_pool.csv`（重叠剔除后） | 与 Gold valid/test 隔离 |
| 所有随机过程 `seed=42` | 可复现 |

## 4. 方法设计

### 4.1 诊断框架（已完成，作动机证据）

**显式/隐式切分**（Task 1）：对每个 Gold 活跃标签对，用 oseti `analyze_detail()` 判定 explicit / implicit。输出 `data/absa_explicit_implicit_tags.csv`。

**子集诊断**（E2）：在 E1 checkpoint 上按 `source` 拆分 test 集，量化显式/隐式 F1 差距。

### 4.2 ABSA 基线（E1，已完成）

| 组件 | 配置 |
|------|------|
| 编码器 | XLM-RoBERTa-base |
| 损失 | ASL（γ_neg=4.0, clip=0.05），无 pos_weight |
| 数据 | Gold annotated-only |
| 角色 | 所有方法的**统一对比起点** |

### 4.3 分项评分弱监督预训练（E7，核心方法）

**阶段 1 — 面板预训练**：

| 组件 | 配置 |
|------|------|
| 输入 | 评论全文（`review_text`） |
| 标签 | 6 项分项评分二分类（≤2 vs ≥3），0 为缺失掩码 |
| 模型 | XLM-R + 6 头分类（共享 encoder） |
| 数据 | `panel_train_pool.csv`（重叠剔除后的 2024 面板） |
| 训练 | 1–2 epoch；按 batch 流式加载（避免 OOM） |
| 验证 | 面板内部 90/10 切分（`seed=42`，与 Gold 切分独立） |

**损失**：6 头 BCE 均值，缺失列（rating=0）mask 掉。

### 4.4 Gold 微调（E8，核心方法）

**阶段 2 — ABSA 微调**：

| 组件 | 配置 |
|------|------|
| 初始化 | E7 预训练 encoder |
| 任务 | 14 标签多标签 ABSA（与 E1 相同架构） |
| 数据 | Gold `absa_train.csv` / `absa_valid.csv` |
| 损失 | ASL + 逐标签阈值调优（与 E1 对齐） |
| 对比 | **E1（无预训练）vs E8（有预训练）** |

**微调策略消融**（A2）：
- 全参数微调 vs encoder 低学习率（1e-6）+ 分类头正常 lr（2e-5）
- 冻结 encoder 仅训头（预期最差，作下界）

### 4.5 子集评估（E8-diagnosis）

复用 `tools/evaluate_by_source.py`，对 E8 checkpoint 跑与 E2 相同的显式/隐式子集拆分，回答 RQ3：**预训练增益是否集中在隐式负面**。

### 4.6 可选方法

| 方法 | 实验 | 说明 |
|------|------|------|
| oseti 信度验证 | Task 2 | 300–500 条人工标注 |
| LLM 思维链 | E5 | 隐式子集 100–150 句 |
| 对比学习 | E3/E4（附录） | 若 E8 增益不足再考虑 |

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 面板与 Gold 重叠率高 | 训练池缩水 | 报告重叠率；仍可用未重叠部分 |
| 分项评分列映射错误 | E7 学到错误信号 | Phase 0 用 `absa_asl_v1` 预测验证；写入映射 JSON |
| 弱标签噪声（评分≠文本情感） | E8 无增益 | 加置信度过滤消融；负结果亦有价值 |
| 评论级标签 vs 句子级 ABSA 粒度不匹配 | 预训练增益有限 | 分析章节讨论；可选句子切分后再预训练 |
| 数据许可限制 | 发表受限 | 确认 NII-IDR 协议；不公开原始 TSV |
| E8 总体有增益但隐式子集无改善 | RQ3 不成立 | 仍可发表 RQ2；隐式问题留给未来工作（已发生，见 §6） |
| 算力/内存 | 58 万条 OOM | 流式 DataLoader；gradient accumulation |
| **oseti 信度未经人工核验（RQ5，Task 2）** | Task 1 的显式/隐式切分（E2/RQ3/RQ1 结论皆依赖此切分）缺少独立于 oseti 的真值支撑 | **2026-07-20 决定**：验证样本已就绪（`gold/data/verification_sample_to_annotate.xlsx`，400 句分层抽样），打分工具已就绪（`tools/check_oseti_accuracy.py`）。**人工标注环节本质上需要真人判断，不可由 AI 代为完成后冒充"人工核验"**——若由 LLM 填答案，等同于做了另一个不同的实验（LLM 与 oseti 的一致性，而非独立人工真值）。经与用户确认：**本轮不做，作为论文局限明确写出**；若下学期写作阶段有余力，可自行或委托标注后一条命令跑出信度报告 |
